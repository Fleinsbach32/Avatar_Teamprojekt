## 1. Prompt-Qualität (`app/prompts.py`)

### 1.1 Neuer Abschnitt „Wissensgrenzen" im Base-Prompt

Das größte Problem: KIRA antwortete auf gültige Fragen (Bewerbung, NC, Einschreibung)
mit „Dafür bin ich leider nicht zuständig" — weil die einzige Fallback-Formulierung
für beides galt: nicht-zuständig UND nicht-wissend. Fix: Explizite Regel, die beide
Fälle trennt.

> „Nicht zuständig" → ausschließlich für Themen ohne Bezug zu Studium/KIT.
> Wissenslücke (NC, Fristen, Moduldetails) → ehrlich zugeben + campus.kit.edu.

Außerdem: Wenn eine Modulnummer genannt wird (z.B. M-WIWI-101267), erst in der
Wissensbasis suchen und mit Klarname antworten. Nur falls nichts gefunden, nach
dem Namen fragen.

### 1.2 Antwortregeln verschärft

- „Antworte kurz und präzise" explizit in Persönlichkeit und Antwortregeln.
- Verboten: Floskeln wie „Ich verstehe, dass du wissen möchtest...", „Das ist eine
  gute Frage", „Natürlich". KIRA kommt direkt zum Punkt.
- Verboten: Markdown-Formatierung (*kursiv*, **fett**) — stört die Sprachausgabe.
- Bisherige separate „Länge"-Sektion in Antwortregeln integriert (war redundant).
- Voice-Prompts (DE+EN) ebenfalls um No-Markdown- und No-Floskel-Regel ergänzt.
- Englische Version vollständig synchronisiert.

### 1.3 Tavus _VOICE_CONTEXT verbessert (`app/routes/tavus.py`)

Der kurze Inline-Kontext, den Tavus beim Session-Start erhält, wurde um du-Form
und Keine-Listen-Regel ergänzt.

## 2. RAG-Verbesserungen (`app/rag.py`)

### 2.1 Modul-ID-Direktsuche

**Problem:** Semantische Embeddings taugen nicht für IDs wie „M-WIWI-101267" —
das Modell findet keinen sinnvollen Nachbarn.

**Fix:** Regex `M-[A-Z]+-\d+` erkennt eine Modul-ID in der Frage. Bei Treffer
läuft zuerst eine `where_document={"$contains": module_id}`-Query (Volltext-Match),
bevor die normale semantische Suche startet. Liefert der Volltext-Match Ergebnisse,
werden sie mit einer eigenen Anweisung ans Modell weitergegeben: „Antworte auf
Basis dieses Kontexts, Klarname ohne ID."

### 2.2 Robusterer n_results-Fallback

**Problem:** Wenn ein Studiengang-Filter aktiv ist und die Collection sehr wenige
passende Chunks hat, konnte ChromaDB bei `n_results=3` einen Fehler werfen.

**Fix:** Neue Hilfsfunktion `_query_safe()` fängt den Fehler ab und wiederholt
die Query mit `n_results=1`. Schlägt auch das fehl, wird ein leeres Ergebnis
zurückgegeben.

### 2.3 Chunk-Größe erhöht

`doc[:400]` → `doc[:600]` pro Chunk in der Kontext-Zusammensetzung. Gibt dem
Modell mehr Kontext je Treffer, besonders bei längeren Modulbeschreibungen.

### 2.4 RAG-Anweisung flexibler

Statt „ausschließlich auf Basis des Kontexts" sagt die Anweisung bei gutem Treffer
jetzt: „Nutze den Kontext wenn er zur Frage passt, sonst ignoriere ihn und nutze
allgemeines Hochschulwissen." Verhindert, dass KIRA bei falsch retrievten Chunks
(z.B. Vollmacht statt Einschreibung) trotzdem den falschen Inhalt wiedergibt.

## 3. Web-Crawler (`crawler.py` + `crawl.ps1`)

### 3.1 Crawler

BFS-Crawler (Breiten-Suche) speziell für wiwi.kit.edu plus externe Seeds
(Fachschaft, HOC, ZAK, SLE, KIT.edu). Funktionen:

- **robots.txt**-Compliance (gecacht pro Domain)
- **Shibboleth-Erkennung:** Login-Redirects werden erkannt und übersprungen
- **Stream-Download:** Response-Headers werden vor dem Body geprüft — binäre
  Content-Types und Dateien > 5 MB nie heruntergeladen
- **URL-Blacklist:** PHP-Skripte die immer hinter Login liegen
- **Sentence-aware Chunking:** Chunks bis 300 Tokens, 30 Token Überlappung,
  Satzgrenzen werden respektiert
- **Spracherkennung** (langdetect, optional)
- **PDF-Extraktion** via PyMuPDF (fitz, optional)
- **ChromaDB-Ingestion:** direkt beim Crawl (`--embed`) oder nachgelagert
  (`--fill-db`)
- **Modul-Bewertungen** (`--inject-ratings`): strukturierte Bewertungsdaten aus
  `module_ratings.json` als Chunks in ChromaDB

Warum bricht der Crawler bei wiwi.kit.edu nach ~284 Seiten ab: `ALLOWED_DOMAINS`
enthält nur wiwi.kit.edu — Links von externen Seeds werden nicht verfolgt.
Außerdem ist `max_depth=3` der Standard — depth=3-Seiten erzeugen keine Kinder.
Beides ist bewusst so konfiguriert; wiwi.kit.edu hat schlicht nicht mehr als
~280 öffentlich erreichbare Seiten.

### 3.2 crawl.ps1

Einzeiliges Setup-Skript mit denselben Stamp-Mechanismus wie `run.ps1`:

```
.\crawl.ps1                  # Standard: pip → crawl → fill-db
.\crawl.ps1 -MaxPages 200    # Schneller Testlauf
.\crawl.ps1 -FillDbOnly      # Nur JSONs → ChromaDB einbetten
.\crawl.ps1 -InjectRatings   # Nur Modulbewertungen einpflegen
```

Enthält automatische UTF-16-Erkennung für `requirements.txt` (BOM `FF FE`
→ re-encode als UTF-8 ohne BOM) — notwendig, weil das Write-Tool auf Windows
Dateien im UTF-16-Format speichert, pip damit aber nicht umgehen kann.

### 3.3 requirements.txt

- Encoding repariert: UTF-16 LE mit BOM → UTF-8 ohne BOM (via PowerShell
  `[System.IO.File]::WriteAllText` mit `UTF8Encoding($false)`)
- Neu: `beautifulsoup4>=4.12`, `PyMuPDF>=1.24`, `langdetect>=1.0.9`

## 6. Bekannte Offene Punkte

- **Orientierungspraktikum / Orientierungsprüfungen:** Die MHBs enthalten diese
  Infos, aber die Chunk-Größe (300 Zeichen in `fill_db.py`) zerschneidet die
  relevanten Passagen. Entweder `fill_db.py` auf größere Chunks umstellen oder
  die MHBs neu einpflegen.
- **Studiengang-Dropdown kein sichtbarer Effekt bei Verwaltungsfragen:** Der
  Filter trifft nur auf Modul-Abfragen. Für Einschreibung/Bewerbung/NC sind
  keine Dokumente in der Wissensbasis — KIRA fällt immer auf LLM-Wissen zurück.
  Lösung: studiengangs-spezifische FAQ/SPO-Dokumente in ChromaDB einpflegen.
- **Tavus-Auth:** Credentials in der Tavus-Dashboard-URL müssen manuell gesetzt
  werden (kein automatischer Ablauf).
- **Voice global state** (aus Vortag): Für parallele Sessions Redis einsetzen.
