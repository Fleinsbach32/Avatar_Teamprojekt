## 1. RAG-Reranking mit CrossEncoder

### Motivation

Die bisherige Ein-Stufen-Suche lieferte semantisch ähnliche, aber inhaltlich
schlechte Treffer, weil ChromaDB nur auf Embedding-Ähnlichkeit optimiert.
CrossEncoder-Reranking bewertet Query–Chunk-Paare kontextuell nach.

### Umsetzung

**`app/rag.py`:**

- Neues `rerank(query, docs, top_n)`: lädt
  `cross-encoder/ms-marco-MiniLM-L-6-v2` (via `sentence_transformers`) lazy,
  scored alle Kandidaten-Paare, gibt Top-N sortiert zurück. Fällt bei Import-
  Fehler (kein Torch) auf Reihenfolge aus ChromaDB zurück.
- **Zweistufige Standard-Suche** (`search_knowledge_base`): holt zuerst
  studiengangspezifische Chunks (`program=key`), dann allgemeine (`program="all"`)
  — jeweils bis zu 8 Kandidaten — und rerankt den Pool gemeinsam auf 6 Ergebnisse.
  Dieser Ansatz verhindert, dass allgemeine FAQ-Einträge die spezifischen Modul-
  Handbuch-Treffer verdrängen.
- Modul-ID-Direktsuche und `_query_safe()`-Fallback bleiben erhalten.

**Neue Tests:** `tests/test_prompts.py` wurde um Reranking-Assertions erweitert;
studiengang-Filtertests (`test_studiengang_filter.py`) auf zweistufige Query
angepasst.

## 2. Codebase Cleanup (Planung + Umsetzung)

Strukturiertes Brainstorming → Design-Spec → Implementierungsplan → Umsetzung
per Subagent-Driven Development.

### 2.1 Auth-Entfernung

HTTP Basic Auth wurde vollständig entfernt. Hintergrund: Die Auth-Middleware
blockierte intern aufgerufene Tavus-LLM-Endpoints, was den Voice-Pfad unterbrach.
Da das Projekt über ngrok oder hinter einem eigenen Reverse-Proxy läuft, ist Auth
auf Anwendungsebene hier nicht sinnvoll.

Betroffen: `app/main.py` (kein `check_auth` mehr), `app/auth.py` (gelöscht),
alle Routen ohne `Depends(check_auth)`.

### 2.2 httpx Shared AsyncClient

Vorher öffnete `app/routes/tavus.py` für jeden API-Call ein eigenes
`async with httpx.AsyncClient()` — drei Stellen, dreimal TCP-Handshake.

Fix: Modul-Singleton `_http = httpx.AsyncClient()` (Connection-Pooling),
`aclose()` im `lifespan`-Handler bei App-Ende. Die drei `async with`-Blöcke
wurden durch direkte `await _http.post/delete()` ersetzt.

Test-Impact: 6 Tests in `test_tavus.py` auf `@patch("app.routes.tavus._http")`
umgeschrieben (statt Context-Manager-Mock).

### 2.3 Dead Code entfernt

- `app/routes/avatar.py`: `_VALID_PROVIDERS`-Set und `if provider != "tavus"`-
  Validierung entfernt. Der Endpoint gibt `AVATAR_PROVIDER` jetzt unverändert
  zurück — Validierung gehört nicht in den Config-Endpoint.
- `app/routes/chat.py`: `json` → `json_lib`-Alias entfernt (verwaist),
  Zwischenvariablen `session_id`/`user_input` auf direkte Dict-Zugriffe
  vereinfacht.

## 4. ChromaDB-Rebuild (gecrawlte Daten fehlten)

### Problem

Die `data/chroma_db` war mit einer veralteten `fill_db.py` gebaut worden:
- Pfad zeigte auf `chroma_db/` statt `data/chroma_db/` (wurde als Root-DB betrieben)
- Die 283 JSON-Dateien in `crawled_data/` wurden nie eingebunden
- Folge: Studiengang-Filter funktionierte nicht (kein `program`-Feld in Metadaten)

### Fixes in `scripts/fill_db.py`

1. **Pfadkorrektur:** `CHROMA_PATH = str(PROJECT_ROOT / "data" / "chroma_db")`
2. **Crawled-Data-Ingestion:** neue Funktion `load_crawled_data()` liest alle
   JSON-Dateien aus `crawled_data/`, chunked mit 600/80 Zeichen, speichert mit
   `program: "all"`, `doc_type: "webpage"`, `source: url`
3. **Batch-Größe:** 5000 → 2000 (stabiler auf Windows)
4. **Stale-Reference-Fix:** Collection wird vor jedem Batch neu per
   `get_or_create_collection()` abgerufen (ChromaDB verliert Referenz nach
   Delete+Recreate wenn Collection-Objekt gecacht)
5. **Windows-Encoding:** `→` → `->` in `print()`-Aufrufen (cp1252 hat keinen
   Unicode-Pfeil)
6. **`scripts/inspect_db.py`:** Pfad ebenfalls auf `data/chroma_db` korrigiert

### Rebuild-Ergebnis

```
86 FAQ + 12055 PDF-Chunks + 6379 Web-Chunks = 18520 Einträge gesamt
```

- 86 FAQ-Einträge (de + en), `program: "all"`
- 12055 PDF-Chunks: 10 Modulhandbücher mit Studiengang-Keys +
  6 Info-PDFs mit `program: "all"`
- 6379 Web-Chunks: 283 gecrawlte wiwi.kit.edu-Seiten, `program: "all"`

Studiengang-Filter und zweistufige RAG-Suche danach auf echten Daten verifiziert.

## 5. Chat-UI: Transparentes Design

Schritt-für-Schritt CSS-Anpassung des Chat-Panels (`static/index.html`):

| Element | Alt | Neu |
|---------|-----|-----|
| `#chatPanel` Hintergrund | rgba(0,0,0,0.10) + blur | `transparent`, kein blur |

lesbar aber nicht opak; einheitliches dunkles Farbschema mit weißem Text.
