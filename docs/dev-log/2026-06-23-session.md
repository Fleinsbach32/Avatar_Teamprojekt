## 2. Latenz-Optimierungen

### 2a. In-Memory-Modulindex (B1)

**Problem:** `$contains`-Scans in ChromaDB (z.B. „Was ist Modul Controlling?") dauerten
konstant ~1,4 s unabhängig von Filter-Scope — die ChromaDB-API hat keine Index-Unterstützung
für `$contains`.

**Lösung:** Beim Startup werden alle `doc_type='handbook'`-Chunks in eine Python-Liste
(`_module_index`) geladen. Modul-Namens-Lookups laufen seitdem in O(n) im RAM (~0,3 ms)
statt als ChromaDB-Scan.

- `_build_module_index()` lädt beim ersten Zugriff lazy aus der DB
- `_module_index_get()` ist der gecachte Accessor
- Warmup in `app/main.py` lädt den Index beim App-Start vor

### 2b. Weniger Rerank-Kandidaten (C1)

Zweistufige Suche: Pflicht-Queries 12→9, Normal-Queries 8→6, All-Query 4→3.
Einstufige Suche: 8→6 Kandidaten.
Spart ~15–20 % CrossEncoder-Inferenzzeit.

### 2c. Reranker-Skip bei konfidenten Embeddings (C2)

Wenn die beste Embedding-Distanz < 0,3 ist, wird der CrossEncoder übersprungen
(`RERANK_SKIP_DISTANCE = 0.3`). Spart ~200–600 ms bei eindeutigen Modul-Lookups.

**Betroffene Datei:** `app/rag.py`

## 3. UI-Fixes

### 3a. Mute-Button entfernt

Der TTS-/Mute-Button (`#ttsBtn`) und der gesamte SpeechRecognition-Block wurden aus
`static/index.html` entfernt (~66 CSS-Zeilen, Button-Markup, JS-Block).

### 3b. Auto-Retry bei Service-Fehler

`sendMessage()` wurde in `sendMessage()` + `attemptSend(text, attempt)` aufgeteilt.
Bei SSE-Fehler ohne vorherigen Chunk wird bis zu 2× automatisch wiederholt
(`MAX_SEND_RETRIES=2`, `SEND_RETRY_DELAY=1500 ms`). Guard `gotContent` verhindert
Retry nach erstem gesendeten Chunk.

Fehler-Anzeige:
- Kein Chunk → Retry → nach 2× → `showError(errMessage)`
- Chunk vorhanden, dann Fehler → `showError("Antwort unvollständig — bitte erneut versuchen.")`

### 3c. Avatar-Pausen-Fix (Sentence Buffering)

Gemini-Stream liefert tokenweise Chunks — Avatar-TTS stolperte über halbfertige Sätze.

Lösung in `app/routes/tavus.py`:
- `_flush_sentences(buf, final)` puffert Chunks und gibt nur vollständige Sätze (`.!?`-Ende) weiter
- `_tts_normalize(text)` ersetzt Domain-Punkte durch „ punkt " (z.B. `campus.kit.edu` → `campus punkt kit punkt edu`)

**Betroffene Dateien:** `static/index.html`, `app/routes/tavus.py`

## 4. Railway + Google Drive ChromaDB Bootstrap

### Motivation

Die ChromaDB (6,8 GB) ist gitignored und kann nicht im Docker-Image ausgeliefert werden.
Railway-Deployments brauchen einen automatischen Weg, die DB beim ersten Start zu laden.

### Implementierung

**Neues Modul `app/bootstrap.py`** — `ensure_chroma_db(db_dir: str) -> None`:
- Verzeichnis existiert und nicht leer → sofort return (No-Op, lokale Dev oder Folge-Boot)
- `CHROMA_DRIVE_FILE_ID` nicht gesetzt → Warning-Log + return (CI / lokale Dev ohne DB)
- Sonst: Download via `gdown` (lazy import), Extraktion als `.tar.gz` oder `.zip`
- Stale `.tmp`-Verzeichnis wird vor Extraktion bereinigt (Crash-Resilienz)
- `filter="data"` bei tarfile schützt vor Path-Traversal
- Atomare Verschiebung: Extraktion → `db_dir.tmp` → `os.rename()` → `db_dir`
- Cleanup immer in `finally`-Block

**`app/rag.py`** liest DB-Pfad aus `CHROMA_DB_DIR` (Default: `"chroma_db"`) und ruft
`ensure_chroma_db(CHROMA_DB_DIR)` direkt vor `PersistentClient()` auf.

**`requirements.txt`**: `gdown>=5.0,<6` ergänzt.

**Neue Env-Variablen:**

| Variable | Lokal | Railway |
|---|---|---|
| `CHROMA_DB_DIR` | `chroma_db` (Default) | `/data/chroma_db` |
| `CHROMA_DRIVE_FILE_ID` | nicht gesetzt | `<Drive-File-ID>` |

**Railway-Setup:**
1. Persistent Volume auf `/data` mounten
2. `CHROMA_DB_DIR=/data/chroma_db` und `CHROMA_DRIVE_FILE_ID=<ID>` setzen
3. `chroma_db.zip` (oder `.tar.gz`) in Google Drive hochladen, Freigabe auf „Jeder mit Link"

### Tests

`tests/test_bootstrap.py` mit 6 Tests:
- Non-empty dir → kein Download
- Kein `CHROMA_DRIVE_FILE_ID` → No-Op + Warning
- tar.gz-Extraktion end-to-end (echtes Archiv)
- zip-Extraktion end-to-end (echtes Archiv)
- Leeres Verzeichnis → Download wird ausgelöst
- `gdown` gibt `None` zurück → `RuntimeError`

**Betroffene Dateien:** `app/bootstrap.py` (neu), `app/rag.py`, `requirements.txt`,
`tests/test_bootstrap.py` (neu)
